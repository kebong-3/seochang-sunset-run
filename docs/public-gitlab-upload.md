# 서구 선셋런 공공 GitLab 등록 안내

**광주광역시 서구청 기획실 정의형 제작**  
문서 기준일: 2026년 11월 1일

## 무엇을 등록하나요

ZIP을 압축 해제한 뒤 **`README.md`, `index.html`, `Build/`, `docs/` 등 프로젝트 파일을 폴더 구조대로 저장소에 등록**합니다. 저장소 첫 화면에서 소개글과 사진이 보이려면 루트에 `README.md`가 있고, README가 참조하는 `docs/media/hero.jpg` 등 이미지가 같은 저장소에 있어야 합니다.

GitLab은 저장소에 있는 README를 렌더링합니다. ZIP 하나를 첨부하는 것만으로 압축 안의 파일들이 자동으로 저장소 소스 트리에 펼쳐지지는 않습니다. 안내 근거: [GitLab 파일 관리와 README 표시](https://docs.gitlab.com/user/project/repository/files/).

### 압축을 푼 뒤 확인할 위치

- 저장소 루트: `README.md`, `index.html`, `leaderboard.html`, `START_WINDOWS.bat`, `vercel.json`
- 게임 실행 폴더: `Build/`, `TemplateData/`, `Community/`, `Quality/`
- 안내·이미지: `docs/` 및 그 안의 `media/`
- 로컬 실행 도구: `tools/`

바깥쪽 압축 폴더를 한 겹 더 올려 `프로젝트명/README.md`가 되는 대신, **`README.md`가 저장소 첫 단계에 오도록** 등록합니다. 사진 경로의 대소문자와 확장자도 그대로 유지합니다.

## 방법 1 빈 프로젝트에 Git으로 등록

파일이 많은 패키지는 Git으로 전체 폴더를 한 번에 등록하는 방식이 편리합니다. PC에 Git이 설치되어 있어야 합니다.

### 1단계 공공 GitLab에서 빈 프로젝트 만들기

새 프로젝트를 만들고, 이미 README 등이 들어 있는 프로젝트인지 확인합니다. 아래 명령은 **커밋이 없는 새 빈 프로젝트**를 대상으로 합니다. 프로젝트의 **Clone with HTTPS 주소**를 복사합니다. 공개 범위·심사위원 열람 방식·대회 주제 표시는 해당 대회의 최신 제출 안내에 맞춥니다.

### 2단계 압축을 푼 폴더에서 Git 준비

터미널을 열고 첫 줄의 폴더 경로를 실제 위치로 바꿉니다. 다음은 네 줄씩 실행하는 예시입니다.

```bash
cd "C:/실제경로/선셋런_패키지"
git init
git branch -M main
git add .
```

새로 만든 빈 프로젝트의 HTTPS 주소를 아래 예시 주소 대신 넣고 실행합니다.

```bash
git commit -m "Add SUNSET RUN submission package"
git remote add origin "<공공깃랩에서_복사한_HTTPS주소>"
git push -u origin main
```

인증이 필요하면 공공 GitLab이 허용하는 로그인·토큰 방식으로 인증합니다. 토큰을 명령의 URL에 붙여 저장하지 않습니다. 이름·전자우편 설정이 필요하다는 오류가 나오면 Git의 작성자 설정을 완료한 뒤 `git commit`부터 다시 진행합니다.

### 기존 파일이 있는 프로젝트라면

기존 프로젝트는 먼저 복제한 뒤 그 작업 폴더에 이번 패키지를 반영하고 변경 내용을 검토해 커밋합니다. 기존 작업·브랜치·히스토리를 유지하며 등록하고, 위 빈 프로젝트 초기화 절차나 강제 푸시로 덮어쓰지 않습니다.

GitLab의 저장소 파일 등록·커밋·복제 방식은 [공식 저장소 안내](https://docs.gitlab.com/user/project/repository/)에서 확인할 수 있습니다.

## 방법 2 웹 화면에서 등록

GitLab의 파일 업로드 기능을 이용할 수도 있습니다. 저장소에서 대상 폴더를 열고 파일 추가·업로드 메뉴를 사용해 커밋합니다. 화면에서 여러 파일이나 폴더를 한 번에 처리하지 못한다면, 파일을 계속 나눠 올리기보다 Git 방식으로 전환하는 편이 좋습니다.

웹으로 등록해도 `Build/`, `docs/media/` 등 **상대 경로는 동일하게 유지**해야 합니다. 실제 공공 GitLab의 메뉴와 허용 용량은 해당 서비스 설정에 따라 다를 수 있습니다.

## 가져오기 기능과 ZIP의 차이

이번 ZIP은 **프로젝트 파일을 전달하는 소스·실행본 묶음**입니다. GitLab의 프로젝트 내보내기로 만든 export 파일은 아닙니다. 따라서 ‘GitLab 내보내기 파일 가져오기’ 메뉴에 일반 소스 ZIP을 넣는 방식으로 등록하지 않습니다. GitLab 공식 문서도 저장소 다운로드 압축 파일과 프로젝트 export 파일을 구분합니다. [가져오기 문제 해결 안내](https://docs.gitlab.com/user/import/troubleshooting/)

GitHub 연동 가져오기는 공공 GitLab에서 해당 기능이 지원되고 계정 인증·네트워크 연결이 정상일 때 사용할 수 있습니다. 이 문서는 실제 공공 GitLab에 접속하거나 해당 연동의 성공을 확인한 결과가 아닙니다.

## 등록 후 확인

1. 저장소 루트의 파일 목록에서 `README.md`, `index.html`, `Build/`, `docs/`가 보이는지 확인합니다.
2. 첫 화면의 소개글과 대표 이미지·게임 화면·모바일 이미지가 표시되는지 확인합니다.
3. README의 게임 접속 주소와 구동안내서·AI 개발 기록 링크를 엽니다.
4. 저장소에서 다시 내려받은 파일을 [구동안내서](quickstart.md)에 따라 실행해 봅니다.
5. 참가신청서에는 실제 등록된 프로젝트 주소를 기재합니다. 제출 마감과 수정 가능 범위는 대회 안내에 따릅니다.

사진이 보이지 않으면 `docs/media/`가 누락되었거나 README가 하위 폴더에 들어갔는지 먼저 확인합니다. ZIP만 목록에 보이면 압축을 푼 프로젝트 파일이 저장소에 등록되었는지 확인합니다.
